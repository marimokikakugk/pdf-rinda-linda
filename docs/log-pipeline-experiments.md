## 2026-07-09 Step1 実験1〜2（クラスター認識）

**入力**: 見開きスクショ 1785×1263px ／ **モデル**: claude-sonnet-4-6

### 分かったこと

- **bbox（％座標）は実用になる。** 31クラスターすべてが妥当な位置に出た。「Claudeは座標を返せない」という設計時の懸念は、おおまかな％座標なら杞憂だった
- **Mission文などの巨大タイポグラフィが独立クラスターとして認識された。** 従来方式（1プロンプト一発）で全滅していた内容が「存在するもの」として拾える
- 難しい複合レイアウト（INDEXの3カラム表・右端の縦書き章タブ）も正しく領域化された

### 見つかった問題と対策

| 問題 | 対策 | 結果 |
|---|---|---|
| descriptionに読めない文字を捏造（縦書きタブの内容を創作） | 「確実に読めた文字だけ引用、読めなければ形式のみ記述」を追加 | **解消** |
| 3段組本文を2クラスターに統合（1・2カラム目がひとまとまりに） | 「1カラム＝1クラスター、ガターを数える」を追加 | **効かず**（2回とも）。ただし領域カバレッジとしては取りこぼしなし。カラム分割はStep1で追い込まず、Step2の切り出し内で解決する方針に変更 |

## 2026-07-09 Step2 実験1（切り出し・転写）

**入力**: 上記スクショ（1785px）から bbox+1.5%余白 で切り出し ／ クラスター単位で転写

### 分かったこと

- **解像度がすべてを支配する。** 1785px幅の見開きからの切り出しでは本文カラムの文字が小さすぎ、OCRが崩壊（日本語として不成立）。一方、文字が大きいINDEX・縦書きタブは完璧に転写できた
- **ヒントの誘導バイアスを発見。** Step1のdescription「右カラム本文」をそのままヒントで渡したところ、切り出し画像内に中央カラムが2/3見えているのに右カラムしか転写しなかった。ヒントが「読む範囲の限定」として作用してしまう
- クラスター同士が重なる領域は、それぞれの転写に重複して現れる → Step3で重複除去する前提でよさそう（Yuさん確認済み）

### 対策（次の実験に反映）

1. スクショではなくPDFから scale 3.0 で直接レンダリング（3572×2526px、本番pdf-processorと同条件）。Step1には長辺1568pxのプレビュー、Step2の切り出しには高解像度版を使う（bboxは％なので解像度をまたいで適用可能）
2. ヒントからdescriptionを外しkindのみ渡す＋「推定はあくまで参考、見えるものすべて転写」を明記
3. 切り出し余白を 1.5% → 2.5% に拡大、「見切れた文字も読める範囲で転写（補完禁止）」を追加

## 2026-07-09 Step2 実験2（高解像度レンダリング版）

**入力**: PDFから scale 3.0 レンダリング（3572×2526px）＋上記対策済みプロンプト

### 分かったこと

- **解像度対策は成功。OCRの崩壊が消え、読めた文字はすべて実データと一致**
- 中央カラム（前回ゼロだった箇所）は単体クラスターにはならなかったが、隣接クラスターの切り出し重なりで**全文がどこかの断片に正しく写っている**状態を達成：
  - cluster 23 に冒頭「掲げたミッション」、cluster 24 に3文字目以降〜末尾まで
  - 見切れ文字の誤読あり（「掲げた」→「ざた」）が、断片同士の照合で修復可能な形
- cluster 24 の右カラムに欠け（`を問わず`）があったが、その帯は cluster 31 が拾っていた → **「どの文字もどこかの断片には正しくある」が成立。Step3の重複解決・結合で完成できる見込み**
- 組織図（内閣・●●省・デジタル庁のダイアグラム）の文字要素が記号的表現も含めて正しく転写できた

### 導いた結論

- 断片の重なりはバグではなく資産。Step3は「重複除去＋見切れ修復＋構造推測」を担う
- 図・ダイアグラムは文字転写だけでなく「[図の説明: 〜]」（要素間の関係を伝える代替テキスト）を出させる方針に（アクセシビリティ目的に直結）→ Step2にkind分岐を実装

### 理想のゴール像（Yuさんの言葉から）

組織図のような図は、テキスト羅列ではなく「これはダイアグラムである」と認識した上で、
「内閣→省→庁と線で繋がる内閣府や●●省や▲▲庁、デジタル庁は内閣から直接線で繋がっている」
のような、目の見えない人が構造を理解できる代替テキストが出てくること。

## 2026-07-10 Step3 実験1（パイプライン一周）🎉

**構成**: Step1（プレビュー1回）→ Step2（全31クラスター、視覚要素の代替テキスト化を含む）→ Step3（統合1回）

### 結果：理想形にきわめて近い最終Markdownが出た

- 従来方式で全滅していた Mission/Vision/Values の大テキスト・本文がすべて入った
- 中央カラム「掲げたミッションは〜」が断片照合で完全な形に修復された（「ざた」誤読も解消）
- cluster 24で欠けた「官民を問わず」も隣接断片から正しく統合された
- イラストの代替テキストが位置対応で全数入った
- 組織図に [図の説明: 内閣を頂点とした階層型の組織図で〜内閣から直接線で繋がっている] が付いた（理想のゴール像を初回でほぼ達成）

### 残った問題と対策

| 問題 | 深刻度 | 対策 |
|---|---|---|
| 図の中の文字が平文としても残留（内閣・●●省…） | 低（許容範囲） | Step3の帰属ルールで様子見 |
| 装飾ビュレット（●+白三角）が「❶」になる → スクリーンリーダーが項番と誤読 | 中 | 対応する文字がない装飾記号は「●」に統一、丸数字禁止（Step2/Step3両方に追加） |
| 1つの文が2つの`#`見出しに分割（誰一人取り残されない、／人に優しいデジタル化を。） | 中 | 「文・キャッチコピーを複数見出しに分割しない」をStep3に追加 |
